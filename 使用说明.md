# DualSense Mapper — User Guide

Map a PS5 DualSense controller to Windows keyboard and mouse. Portable, no installer,
no autostart — close the app and the controller instantly goes back to being an
ordinary gamepad.

**English** · [中文说明](#中文说明)

---

## Dependencies live in `.venv`, not in your system Python

The first time you run `run.bat`, it creates a `.venv` virtual environment in this
folder and installs everything into it.

Two reasons:

1. **It does not pollute your global environment.** Installing straight into the
   system Python overwrites versions other software depends on — bump Pillow and
   suddenly something like Real-ESRGAN stops working.
2. **It sidesteps legacy baggage.** If a Python install was upgraded in place from
   an older version, it may still contain `easy_install`-era `.egg` packages.
   An egg inserts itself at the front of `sys.path`, outranking anything pip
   installs, and pip cannot overwrite it. The classic symptom is
   `TypeError: type 'typing.TypeVar' is not an acceptable base type`.
   A fresh venv has none of that.

Don't want it any more? Delete the `.venv` folder. The next run rebuilds it.

---

## Double-clicking a `.bat` does nothing?

Run **`check.bat`** first. It prints your Python version, which packages are
missing, and whether the controller was detected.

If even that does nothing, you probably don't have Python. Install one from
<https://www.python.org/downloads/> — **make sure you tick "Add Python to PATH"
at the bottom of the first screen.** Skip that and nothing afterwards will work.

Python **3.10 – 3.13** is required, and it must be a normal build. Free-threaded
("no-GIL") builds such as 3.13t and 3.14t will not work, because the C extensions
this project needs have no matching wheels. **3.12 is the recommended version.**

Still stuck? Do it by hand: hold `Shift` and right-click in this folder →
"Open PowerShell window here", then paste these one at a time:

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Errors stay visible in the window that way — screenshot it and send it back.

## Building the portable package (once is enough)

Double-click **`release.bat`**. It will:

1. Install the build dependencies into the project-local `.venv` — **the system
   Python is never touched**
2. Package with PyInstaller
3. Produce, under `output\`:
   - `DualSenseMapper.zip` — this is the thing you hand to someone
   - `DualSenseMapper\` — the same thing, already extracted

The `output` folder opens automatically when it finishes. **Click it only once** —
the script has a re-entry guard, and a second window will simply tell you it is
already running and exit.

What comes out of the zip is just two things: `DualSenseMapper.exe` and an
`_internal\` folder (the Python runtime and the UI). **Double-click the exe and it
runs — no Python, nothing to install.** The config file `ps5mapper.config.json` is
created next to the exe on first run, so copying the whole folder moves your setup
to another machine.

It uses **onedir, not onefile**. Onefile unpacks itself into `%TEMP%` on every
launch: slow to start, and it scatters files outside the folder. With onedir
everything sits where you put it and startup is fast.

The only system dependency is the **Edge WebView2 runtime**, which ships with
Windows 10/11 alongside Edge. Nothing for you to do.

**The factory defaults are baked in.** `ps5mapper/default_config.json` is generated
from a real working config and compiled into the exe. It is what you get on first
run, on profile "reset", and on "new profile". To change the factory defaults, run
`python tools/bake_defaults.py some.config.json` and rebuild.

## Running it

### From source (fast to iterate on, good for debugging)

Double-click `run.bat`. The first run installs dependencies; after that it opens
in a second.

### As a portable exe

Double-click `release.bat` and wait a few minutes. The result is in `output\`.

The build comes out around 30–50 MB. The UI uses the Edge WebView2 runtime that
Windows already has, so there is no extra runtime to install — copy the folder to
another machine and it just runs.

## What's in the UI

| Page | What it does |
|---|---|
| **Button mapping** | All 17 inputs are remappable. Click a label to open the editor, or click the button on the controller diagram. Presets are grouped into Common / Mouse / Editing / Browse & scroll / Window / In-app |
| **Adaptive triggers** | Resistance feel for L2/R2. **Wall position** and **key fire point** are two separate settings: the wall starts at "resistance wall start" and spans a stretch beyond it, and by default the key fires only once you **push through the whole wall**. You can switch to a custom depth or fire-at-bottom instead |
| **Touchpad** | Hybrid pointer mode, tap-to-click, double-tap drag, press drift correction, two-finger scroll (**vertical and horizontal are configured separately**), pinch zoom, edge strip for volume |
| **Sticks & mouse** | Deadzone, speed, acceleration curve with a live graph. When a stick acts as a scroll wheel, vertical and horizontal are again separate |
| **Profiles** | Multiple configs, switched by controller button or tray menu. You can **duplicate** (full copy, then edit), **rename** (double-click the name or use the button), reset, delete. The color set here is the **switch-notification color**, not the persistent one |
| **Lighting** | Lightbar color and effect, brightness, profile-switch flash, player-LED battery display, mic LED |
| **Settings** | Emergency pause combo, startup behavior, recording device |

Buttons you press on the controller **highlight live** in the UI, and trigger
pressure shows as a live bar — so you can hold a button while tuning its settings.

## Things worth knowing

**Emergency pause**: `L1 + R1 + touchpad click` by default, all three at once.
Press once to stop all mapping, press again to resume. Use it when you want to
play a game without closing the app. It cannot be deleted.

**Voice input**: bound to the mic-mute button by default, and all it sends is
`Win+H`. There is no "voice feature" in this program — it is an ordinary key
combination mapping. You can move it to any button, or delete it.

Win+H has some Windows-side limits: it needs an internet connection, focus must be
in a text field, and it shuts itself off after a pause in speech. For long-form
dictation, rebind to Voice Access instead (Settings → Accessibility → Speech,
offline models available).

**Touchpad gestures**: behavior matches a Windows precision touchpad on a laptop.

- **One-finger tap** = left click, **two-finger tap** = right click, neither needs
  a physical press
- **Tap, then immediately press and hold** = drag (the "tap-and-a-half" gesture)
- Physical press still works as before, as does press-and-hold to drag

**Why the cursor drifts when you press down**: the touchpad is one big button, and
**the switch closes only at the very end of the travel**, by which point your
fingertip has already flattened and skidded a millimetre or two. In other words the
cursor has already moved *before* the click registers, so "freeze the pointer when
a click arrives" is simply too late. This pad has only 1920×1080 units and reports
at 250 Hz, which makes one millimetre translate to several times the movement it
would on a laptop — hence how obvious it is.

The program copies two tricks from laptop drivers: buffer the last few tens of
milliseconds of movement and **rewind** it when a click arrives, then apply a
**drag threshold** during the hold so dragging only starts once you cross it. The
default "drift only" mode rewinds just the slow, short movement that clearly came
from the press — if you swipe fast and tap at the end, that movement was real and
does not get yanked back. All three switches are on the Touchpad page; if dragging
feels sluggish to start, lower the threshold or set it to zero.

**These thresholds were measured on a real controller** (2026-08-23, over Bluetooth):

| Measured | Result | Resulting threshold |
|---|---|---|
| Tap duration | 78 – 156 ms (median 110) | accept 40 – 200 ms |
| Tap movement | 5.1 – 71.1 units (median 13.3) | accept 3 – 90 units |
| Slide in the 100 ms before a press | 2.2 – 114.9 units (median 27) | rewind cap 150 units |
| Ghost tail after a tap | 0 – 32 ms | no correction needed, use the raw duration |

The important one: **the measurement overturned a design assumption.** The plan had
been to strip the ghost tail using "frozen coordinates = finger already lifted".
The data showed that **a stationary real finger produces identical coordinates too** —
held still for 4 seconds, 1931 of 2116 frames matched the previous frame exactly,
with one unbroken 320 ms stretch. Under that rule, resting a finger on the pad would
have fired a phantom click. Fortunately the same data showed the correction was
unnecessary (the tail is only 32 ms), so the whole path was deleted.

Ghost rejection instead uses a **movement floor**: ghost contacts have frozen
coordinates and therefore zero movement, while even the lightest real touch jitters
by 5 units or more. About 24% of idle frames falsely report a contact — without that
floor, a controller sitting on a desk would click by itself.

The rewind threshold is also measured in **raw touchpad units, not pixels** — in
pixels, changing your sensitivity would throw the drift correction off with it.

**Controller microphone**: Windows only sees it over USB. It does not work over
Bluetooth — that is Sony's proprietary protocol, unsupported by Windows, not a bug
in this program. On Bluetooth, recording uses your default PC microphone.

**Adaptive triggers drain the battery**: leaving resistance on noticeably shortens
runtime. There is a master switch at the top right of the Triggers page; turning it
off does not affect your button bindings.

**Lighting**: the controller has three lights and the program controls all of them.

- **Lightbar** (both sides of the touchpad, full color): shows a **global color**
  plus an effect (steady / breathe / off). Switching profiles flashes that profile's
  notification color for a few seconds, then returns to the persistent effect.
- **Player LEDs** (the five small white lights below the touchpad): a rough battery
  indicator with only three levels — below 10% lights the center one, 11–25% lights
  the two near the center, 26% and above lights the four outer ones. While charging,
  these three patterns cycle outward from the center.
  Deliberately not finer-grained, and deliberately never all five: the row is not
  evenly spaced physically (the middle three sit closer together), so all-on looks
  lopsided. For the exact percentage, the title bar always shows it.
  Plugged into USB the controller is always charging, so this display mainly
  matters over Bluetooth.
- **Mic LED** (the orange light on the mic button): by default it reads
  **the real Windows microphone-in-use state** — the same data the taskbar mic icon
  is drawn from — so when Win+H stops itself after a silent pause, the light goes
  out with it. The cost is that other apps holding the mic (Discord, a browser,
  meeting software) will light it too. The Lighting page can switch back to
  "keypress counting", but that mode **desynchronizes from auto-stop**: Win+H stops
  on its own while the program still thinks it is recording, and the next press
  toggles the wrong way.

**The lightbar and player LEDs have a protocol prerequisite**: after power-on the
controller runs its own lightbar fade animation, and when that ends **the firmware
keeps holding the lightbar and player LEDs, ignoring every color the host sends.**
You must first send a "claim" command (`valid_flag2 = 0x02` +
`lightbar_setup = 0x02`) to take control. The program now sends this automatically
every time it connects. The mic LED goes through a different path (byte 8 of the
output report) and is not subject to this — which is why forgetting the claim
produces the distinctive symptom "the mic LED works, the lightbar and player LEDs
do nothing at all".

The lightbar has **no hardware animation** — breathing is drawn by the program
sending a report every frame at 30 Hz, which costs a little Bluetooth bandwidth and
a little battery. So steady is the default: when steady, the output thread drops to
4 Hz and skips duplicate reports, sending almost nothing. To save the most power,
set the effect to "off" or pull brightness to zero.

"Toggle controller lighting" is a built-in action you can bind to any controller
button.

While mapping is paused the lightbar goes dark red and stops animating, and the
other two lights go out — making it impossible to misread the paused state. On exit
the lightbar returns to the PS5 factory blue.

**Anti-cheat games**: games with anti-cheat (Valorant, Apex, etc.) block synthetic
input, so none of this works there. Desktop use and chat apps are fine.

**Elevated windows**: to send keys to a window running as administrator — Task
Manager, for instance — this program must also be started as administrator.

## Future: showing an AI assistant's status on the lightbar

**Not built**, but the approach is worked out and recorded here so it isn't lost.

The key point: **you cannot read it, you can only be told.** No system API lets a
program ask "is the AI thinking right now" — it has to work the other way around,
with the AI tool knocking on the door when its state changes. The three tools differ
enormously:

| Tool | What you can get | How to hook it |
|---|---|---|
| **Claude Code** (terminal) | Everything: work started / running a tool / waiting for your approval / done | hooks in `~/.claude/settings.json`, using the `UserPromptSubmit`, `PreToolUse`, `PermissionRequest` and `Stop` events |
| **Codex CLI** | Only "done" | `notify` in `~/.codex/config.toml`, which has a single `agent-turn-complete` event. Note its JSON arrives as the **last command-line argument**, not on stdin |
| **Cowork** (desktop app) | Not possible | No local hooks, no state file, no local API. The only official route is OpenTelemetry export, which needs a Team/Enterprise plan plus your own collector — not worth it for a light |

The chosen mechanism is a **state file plus polling**: the hook writes one line of
status to a temp file, the program reads it every 200 ms. No open port, no firewall
prompt, and any language can push to it with a one-line command — more reliable than
a local HTTP port, faster than spawning a process.

**Do not** poll window titles, watch CPU usage, or diff screenshots. Approaches like
that work today and break tomorrow, and when they break you won't know — worse than
not having the feature.

## Troubleshooting

**Controller not found**: try a different cable (some are charge-only); close
anything that grabs the controller exclusively, such as Steam or DS4Windows.

**Buttons do nothing**: check whether emergency pause is active (the bottom of the
sidebar will say so); or the target window is running elevated.

**Pointer drifts on its own**: stick drift — raise the deadzone on the
Sticks & mouse page.

**No trigger resistance**: make sure the master switch at the top right of the
Triggers page is on, and that "enable resistance for this trigger" is on for that
specific trigger. Run `check.bat` to confirm the controller is connected at all.

第一次运行 `run.bat` 时会在这个文件夹下建一个 `.venv` 虚拟环境，所有依赖都装在里面。

这样做有两个原因：

   优先级高于 pip 装的新版本，pip 升级也盖不掉，典型症状是
   `TypeError: type 'typing.TypeVar' is not an acceptable base type`。
   全新的 venv 没有这个包袱。

不想要了直接删掉 `.venv` 文件夹即可，下次运行会重建。

## 几个要知道的点

**紧急暂停**：默认 `L1 + R1 + 触摸板按下` 三键同按。按一下停掉全部映射，
再按一下恢复。想玩游戏又不想关程序时用这个。它不能被删除。

**语音输入**：默认绑在麦克风静音键上，发送的就是 `Win+H`。
程序里没有「语音功能」这个东西 —— 它只是一条普通的组合键映射，
你可以拖到任何键上，也可以删掉。

Win+H 有几个 Windows 自身的限制：需要联网、焦点得在文本框里、
说完停一会儿它会自动关。想长时间口述可以改绑 Voice Access
（设置 → 辅助功能 → 语音，可下载离线模型）。

**触摸板手势**：行为对齐 Windows 笔记本的精准触摸板。

- **单指轻点** = 左键，**双指轻点** = 右键，都不用把板子压下去
- **轻点一下、紧接着再按住不放** = 拖动（笔记本上的「一次半」手势）
- **物理下压**照旧，按住不放拖动也照旧

**为什么下压时光标会飘**：触摸板是整块压下去的按键，**开关在按压行程的最后才闭合**，
而手指在这段行程里已经压扁、打滑了一两毫米。也就是说光标是在你按下去**之前**就飘走的，
单纯「收到点击就冻住指针」根本来不及。这块板子只有 1920×1080 个单位又上报 250Hz，
同样一毫米的滚动换算出来比笔记本大好几倍，所以特别明显。

程序照抄了笔记本驱动的两招：缓存最近几十毫秒的位移，收到点击就**倒回去**；
再在按住期间设一个**拖动门槛**，滑过门槛才开始拖。默认的「只倒漂移」模式只撤销
又慢又短、看着就是压手指压出来的那段 —— 你要是正快速划过去顺手点一下，那段位移是真的，
不会被往回拽。三个开关都在触摸板页里，嫌拖动起步迟钝就把门槛调小或归零。

**这些阈值是在真手柄上量出来的**（2026-08-23，蓝牙连接）：

| 实测项 | 结果 | 对应阈值 |
|---|---|---|
| 轻点时长 | 78 ~ 156ms（中位 110） | 认 40 ~ 200ms |
| 轻点位移 | 5.1 ~ 71.1 单位（中位 13.3） | 认 3 ~ 90 单位 |
| 下压前 100ms 的滑动 | 2.2 ~ 114.9 单位（中位 27） | 倒回上限 150 单位 |
| 轻点后的幽灵尾巴 | 0 ~ 32ms | 不需要修正，直接用原始时长 |

其中最要紧的一条：**实测把原来的一个设计假设推翻了。** 本来打算用
「坐标冻住 = 手指已经抬起」来剥掉幽灵尾巴，实测发现**静止的真手指坐标同样是
逐帧完全相同的** —— 放着不动 4 秒，2116 帧里 1931 帧和上一帧一模一样，
最长连续 320ms 纹丝不动。照那条规则做，手指往板子上一放就会误发一次点击。
好在同一份数据也说明根本不需要那个修正（尾巴只有 32ms），所以整条路直接删掉了。

防幽灵改用**位移下限**：幽灵触点坐标卡死、位移恒为 0，而真手指再轻的一点也有
5 个单位以上的抖动。空闲时约 24% 的帧在误报有触点，没有这条下限，
手柄搁在桌上自己就会乱点。

另外倒回的判据从「像素」改成了**触摸板原始单位** —— 用像素的话，你一调灵敏度
防漂移就跟着失准。

**手柄麦克风**：只有 USB 连接时 Windows 才认得到它。蓝牙下用不了 ——
这是 Sony 的私有协议，Windows 不支持，不是程序的问题。
蓝牙时录音会走电脑默认麦克风。

**自适应扳机耗电**：长期开阻力会明显加快耗电。扳机页右上角有总开关，
关掉不影响按键绑定。

**灯光**：手柄上有三盏灯，程序都能控制。

- **灯条**（触摸板两侧，全彩）：常驻显示一个**全局颜色** + 一个灯效（常亮 / 呼吸 / 关）。
  切换配置档时会先亮成那一档的提示色几秒，再回到常驻灯效。
- **玩家灯**（触摸板下方 5 个白灯）：粗略显示电量，只分三档 ——
  10% 以下亮最中间一颗，11~25% 亮靠近中间的两颗，26% 以上亮除中间外的四颗；
  充电时这三个图案由内往外循环点亮。
  刻意不分得更细，也刻意不用五颗全亮：这排灯物理上排布不均匀（中间三颗挨得更紧），
  全亮看着是歪的；而想知道确切电量，标题栏一直写着百分比。
  插着 USB 时手柄一直在充电，这个显示主要在蓝牙下有意义。
- **麦克风灯**（麦克风键上的橙灯）：默认读 **Windows 真实的麦克风占用状态**
  （任务栏那个麦克风图标就是靠同一套数据画的），所以 Win+H 静音几秒自动停掉时
  灯会跟着灭。代价是别的应用占着麦克风（Discord、浏览器、会议软件）它也会亮。
  灯光页里可以切回「按键计数」，但那种模式**会和自动停止对不上** ——
  Win+H 自己停了程序还以为在录，下一次按键的开关方向就整个反过来。

**灯条和玩家灯有个协议上的前提**：手柄上电后会自己跑一段灯条渐变动画，动画结束后
**固件继续占着灯条和玩家灯，主机发的颜色全部被无视**。必须先发一条「抢灯」指令
（`valid_flag2 = 0x02` + `lightbar_setup = 0x02`）把控制权拿过来。程序现在每次连上
手柄都会自动发这一条。麦克风灯走的是另一条路（输出报告第 8 字节），不受这个限制 ——
所以漏了抢灯时的症状会是「麦克风灯好使，灯条和玩家灯完全没反应」。

灯条**没有硬件动画** —— 呼吸是程序以 30Hz 逐帧发报告画出来的，蓝牙下会占一点带宽、
多耗一点电。所以默认是常亮：常亮时输出线程会自己降到 4Hz 并跳过重复报告，
基本不发包。想彻底省电就把灯效设成「关闭」，或者把亮度拉到 0。

「开关手柄灯光」是一个内置功能，可以绑到任意手柄按键上随时切。

映射暂停时灯条变暗红并停掉动效，另外两盏灯熄灭 —— 让「停了」这件事不可能被看错。
退出程序时灯条恢复成 PS5 出厂那个蓝。

**反作弊游戏**：带反作弊的游戏（瓦罗兰特、Apex 等）会拦截模拟输入，
这套东西在那些游戏里不能用。日常桌面和聊天软件没问题。

**管理员权限窗口**：如果要往任务管理器这类以管理员权限运行的窗口发按键，
程序也得用管理员身份启动。

## 将来：让灯条显示 AI 助手的工作状态

这个功能**目前没做**，但方案已经想清楚了，记在这里以免忘记。

关键点：**读不到，只能被通知**。没有哪个系统接口能让程序去问「AI 现在在想事情吗」，
只能反过来 —— 让 AI 工具在状态变化时主动来敲门。三个工具的情况差别很大：

| 工具 | 能拿到什么 | 怎么接 |
|---|---|---|
| **Claude Code**（终端） | 全套：开始工作 / 跑工具中 / 等你授权 / 完成 | `~/.claude/settings.json` 里配 hooks，用 `UserPromptSubmit`、`PreToolUse`、`PermissionRequest`、`Stop` 四个事件 |
| **Codex CLI** | 只有「完成」 | `~/.codex/config.toml` 里的 `notify`，只有 `agent-turn-complete` 一个事件。注意它的 JSON 是当**最后一个命令行参数**传的，不是 stdin |
| **Cowork**（桌面应用） | 做不了 | 没有本地 hooks / 状态文件 / 本地 API。唯一官方途径是 OpenTelemetry 导出，要 Team/Enterprise 套餐加自建 collector，为点个灯不值得 |

实现方式定的是**状态文件 + 轮询**：hook 往临时文件里写一行状态，程序每 200ms 读一次。
不开端口、不碰防火墙、任何语言一行命令就能推 —— 比本地 HTTP 端口稳，比起进程快。

**不要**用轮询窗口标题、盯 CPU 占用、截屏比像素这类办法。那种东西今天能用明天就坏，
而且坏了你还不知道，比没有更糟。

## 目录结构

```
main.py                 入口

  dualsense.py          HID 读写：报告解析、灯条、震动、扳机（USB + 蓝牙）
  triggers.py           自适应扳机效果的字节生成、阻力墙位置与触发点判定
  lights.py             灯光状态计算（呼吸波形、亮度、电量分档、优先级）
  gyro.py               陀螺仪体感瞄准
  winput.py             SendInput 封装：键盘、组合键、鼠标
  engine.py             映射引擎主循环 + 触摸板手势
  config.py             配置读写与出厂默认
  default_config.json   烘焙进来的出厂默认（tools/bake_defaults.py 生成）
  audio.py              切换默认录音设备
  app.py                窗口 + 托盘 + JS 桥
  ui/index.html         界面（单文件 HTML）

tests/                  单元测试（不需要手柄）
tools/                  打包与多语言辅助脚本
```

## 出问题怎么办

**找不到手柄**：换一根数据线（有些线只充电不传数据）；把 Steam、DS4Windows
这类会独占手柄的程序先关掉。

**按键没反应**：看看是不是被紧急暂停了（侧栏底部会显示「映射已暂停」）；
或者目标窗口是管理员权限。

**指针自己乱飞**：摇杆漂移，把「摇杆与鼠标」页的死区调大一点。

**扳机没有阻力**：确认扳机页右上角总开关是开的，且那根扳机的
「启用这根扳机的阻力」也是开的。跑一遍 `check.bat` 确认手柄确实连上了。
