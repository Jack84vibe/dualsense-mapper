# 界面翻译表

每个语言一个 json，按 **id** 对齐。

| 文件 | 是什么 |
| --- | --- |
| `_source.json` | id → 简体原文。**生成的，别手改** |
| `_runtime.json` | 由 JS 拼出来、抓不到的原文清单。加这类文字时手动补进来 |
| `zh-TW.json` | 繁體 |
| `en.json` | English |

id 是原文的 sha1 前 8 位。所以：

* 原文没改，id 就不变，已有译文不受影响
* 原文改了，id 跟着变 → 旧译文自动作废，生成脚本会报「缺失」。
  这是刻意的：中文改了，译文本来就该重翻，不该让旧译文默默留着

## 加一门新语言

1. 复制 `_source.json` 成 `<语言代码>.json`，比如 `ja.json`
2. 把 `"_name"` 改成这门语言自己的写法（设置页上显示的就是它）
3. 把每一条的值换成译文。**留空或删掉的条目会退回简体**，不会变成空白
4. 跑 `python tools/build_i18n.py`

界面会自动发现这个目录下的所有语言，设置页的选项不用改代码。

## 改完界面要跑的两个脚本

```
python tools/build_i18n.py     # 收原文、补繁体、生成 ui/i18n.js
python tools/audit_i18n.py     # 反过来查：切成英文，看哪里还剩中文
```

**第二个不能省。** 收原文靠的是「把界面点一遍再遍历 DOM」，
所以**脚本没点开的界面状态，它的文字就等于不存在** —— 不报错，
只是那块地方永远是中文。按键编辑器就这么漏过一整版：
收集脚本里只有一句 `click('.tag')`，只打开了第一个热点，
另外三种形态（扳机、摇杆、十字键）一句都没收到，一百多处中文没人发现。

`audit_i18n.py` 是反着查的：切成英文，凡是还显示中文的就是问题，
并且会告诉你是「没收进表」还是「收了但没套上」——这两种的修法完全不同。
它还会改绑定、清绑定、关摇杆、切双段扳机再查一遍，
专抓「默认配置下看着没事、一改就翻不了」那类。

## 运行时拼出来的句子

像「复制 · Ctrl+C」「已绑 3 / 4 个方向」这种，**整句不能进翻译表** ——
换个绑定它就变成另一句，表里那条立刻作废，界面退回中文。
做法是：固定的片段各自 `t()` 查表，变化的部分原样拼，
然后给装它的元素打 `data-dyn`，让扫描器整个跳过。

## 注意

* 译文要保留原文里的标记（`<b>`、`<br>`、`<em>`）。少一个闭合标签，
  那一块的排版会塌掉。`tests/test_i18n.py` 会检查这件事
* 语言名（简体中文 / English / …）永远写各自的母语，不翻译
* 配置档名字、你自己改过的按键标签属于用户数据，不在翻译表里
* 繁体默认由 `opencc(s2twp)` 自动转换；**手工改过的条目会保留**，
  不会被下次自动转换覆盖
